## 1. Purpose

The adapter layer is the *only* place broker-specific code may exist
(Architecture R2). Adapters translate a minimal, strict internal order/account
model into broker APIs. Swapping brokers must never require touching the core
engine.

## 2. Internal Models (illustrative interface)

```python
class BrokerAdapter(Protocol):
    """Contract every adapter must satisfy. Certification suite tests all of it."""

    name: str
    caps: BrokerCapabilities      # fractional, order_types, gtc, rate_limit, sessions

    def get_account(self) -> AccountSnapshot: ...        # cash, NAV, buying_power
    def get_positions(self) -> list[Position]: ...       # symbol, qty, avg_price
    def get_order(self, client_order_id: str) -> OrderState: ...
    def place_order(self, order: ApprovedOrder) -> BrokerAck: ...
    def cancel_order(self, client_order_id: str) -> CancelResult: ...
    def get_recent_fills(self, since: ts) -> list[Fill]: ...

class ApprovedOrder:      # only the Risk Manager can construct (R3 / INV-2)
    client_order_id: str  # uuid7 — idempotency key (FR-EX-02)
    symbol: str
    side: Side
    qty: Decimal          # fractional if caps.fractional else whole
    type: OrderType       # market | limit
    limit_price: Decimal | None
    tif: TimeInForce
    risk_token: RiskApproval
```

Rules embedded in the types:

1. `ApprovedOrder` is constructible **only** via the risk manager (module
   boundary + constructor test) — the engine cannot even express an
   un-vetted order.
2. `client_order_id` is generated by the core, never by the adapter.
3. Adapters never log secrets; they log request IDs only (SEC-03).

## 3. Error Taxonomy & Retry Semantics (FR-EX-06)

| Class | Examples | Adapter behavior |
|---|---|---|
| Transient | network timeout, HTTP 5xx, rate limit 429 | bounded exponential backoff (tenacity), max 3, then surface as `Unavailable` |
| Permanent | validation error, insufficient funds, bad symbol, auth rejected | no retry; surface with broker detail (sanitized) |
| Unknown-state | timeout **after** submit, ambiguous ack | return `UnknownState(client_order_id)` → core queries before acting (FR-EX-03); **never re-submit** |
| Maintenance | broker maintenance window | `Unavailable`, session marks degraded, fail-closed |

## 4. Rate Limits & Politeness

- Every adapter declares `rate_limit` (requests/min) and enforces client-side
  throttling *below* broker limits (FR-EX-05).
- Circuit breaker: after N consecutive failures, adapter reports `Unavailable`
  for a cooldown — no hammering.
- All usage stays inside published ToS; no scraping, no undocumented endpoints
  (RL-5, SEC-15).

## 5. Adapter Certification (contract test suite)

A shared pytest suite runs against **every** adapter (paper/sandbox endpoints).
No adapter merges without passing. Coverage includes:

1. Account/position snapshot mapping (known fixtures).
2. Order lifecycle: new → ack → fill/cancel; state mapping incl. exotic states.
3. **Idempotency:** duplicate `place_order` with same `client_order_id` → no
   second order, same ack (FR-EX-02).
4. **Unknown-state drill:** injected timeout after submit → adapter returns
   `UnknownState`; resolution by `get_order` (FR-EX-03).
5. Error taxonomy mapping for a fixture catalog of broker error payloads.
6. Rate-limit backoff behavior.
7. Capability-flag honesty: adapter fails closed if asked for unsupported
   order features.

## 7. Wealthsimple-Specific Considerations (pre-integration notes)

1. **Access:** waitlisted program; apply at P2 start (CT-01); if unavailable by
   G3, live phase slips — never ships against unofficial endpoints.
2. **Scopes:** must be trade-execution-only. No withdrawal/transfer scope may
   exist on the key (SEC-02). If scopes cannot be constrained, the adapter is
   rejected — this is a hard gate.
3. **FX friction:** currency conversion on US-listed trades historically ~1.5%
   (verify current schedule, CT-04) — strategy design and cost model must
   account for it; prefer holding USD in a USD sub-account to avoid repeated
   round-trips.
4. **Fractional shares:** support matrix to verify (OQ-02) — affects position
   sizing granularity at CAD 2k capital.
5. **Order types:** MVP needs market + limit + day/GTC only; anything exotic is
   ignored by the core regardless of adapter capability.
